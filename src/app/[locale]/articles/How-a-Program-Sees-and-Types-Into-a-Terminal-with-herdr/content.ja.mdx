## ターミナルの画面とは何か

いったん herdr のことは忘れてください。ターミナルの画面は、マス目（セル）が並んだ格子で、各セルには文字が高々一つ入ります。セルのほかに、画面が覚えている位置が一つあります。カーソルです。画面の中身はこれだけです。

    'プログラムが改行を送ります。何も描かれず、カーソルが 2 行 1 列へ移ります。',

色や太字は別のセルではなく、セルに付く属性です。あとで画面をテキストにするときに効いてきます。

覚えておきたいことが二つあります。一つ目、プログラムは「絵を描く」わけではなく、カーソルの位置に文字を書き、カーソルを動かすだけです。二つ目、画面の様子を知るにはセルとカーソルの位置の両方が要ります。片方しか取れないブリッジには、画面の半分しか見えていません。

## 画面を持っているのは誰か：サーバー

`cat` のようなプログラムは、画面と直接話しているわけではありません。疑似端末（PTY）の中で動いています。PTY は、プログラムに「自分には画面とキーボードがある」と思わせる管のようなものです。その管の反対側で、格子を保持している何かが要ります。

herdr でその役を担うのがサーバーです。`herdr status` はクライアントとサーバーを別のものとして報告し、サーバーは Unix ソケットで待ち受けています。herdr のペインの中では、シェルに環境変数（`HERDR_SOCKET_PATH`、`HERDR_PANE_ID` など）も渡されるので、プロセスは自分のペインを見つけられます。格子を持っているのがサーバーなので、ソケットに届くものなら誰でも画面を見られます。この記事の仕掛けは、ほぼこれだけです。

図では省いた、このストリームの細部です。

- フレームは `ESC[?2026h` で始まり、`ESC[?2026l` で終わります。この組は、間の内容を一度の描き直しとして適用してよい、という同期更新の端末慣習で、途中までのフレームが見えることがなくなります。
- `ESC[?25l` は描画中にカーソルを隠し、`ESC[?25h` で再び表示します。その直前の最後の `ESC[行;列H` が、本当のカーソル位置です。
- `ESC[0;39;49m` と `ESC[0m` はスタイルの変更です（ここでは既定の色）。色や太字は同じ系統の別のコードで表されます。`ESC]8;;ESC\` はハイパーリンクの終わり（OSC 8）で、毎回フレームの先頭に、空の形で現れます。
- `--cols` と `--rows` で、その大きさのフレームを頼めます。文字列を短くするため、上では `--cols 10 --rows 4` を使いました。
- ストリームでも、全角文字は二列を使います。`日本` を送ったとき、フレームは `日` を 1 列目、`本` を 3 列目に書き、カーソルは 5 列目で止まりました。

本物のターミナルエミュレーターは要りません。この方言は小さいので、手で適用できます。次は約 50 行のミラーです。ストリームを追いかけて自前の格子を保ちます。サーバーがやっていることそのものです。

```python
"""Mirror a herdr terminal: follow `terminal session observe` and keep our own grid."""
import base64, json, re, subprocess, sys, unicodedata

# One token of the frame dialect: a CSI sequence, an OSC sequence, or plain text.
TOKEN = re.compile(r"\x1b\[([0-9;?]*)([A-Za-z])|\x1b\][^\x1b]*\x1b\\|([^\x1b]+)")

class Screen:
    def __init__(self, width, height):
        self.w, self.h = width, height
        self.cells = [[" "] * width for _ in range(height)]
        self.row = self.col = 0          # the cursor, 0-based inside
        self.cursor_visible = True

    def put(self, ch):
        wide = unicodedata.east_asian_width(ch) in "WF"
        if self.row < self.h and self.col < self.w:
            self.cells[self.row][self.col] = ch
            if wide and self.col + 1 < self.w:
                self.cells[self.row][self.col + 1] = ""   # second half of a wide char
        self.col += 2 if wide else 1

    def apply(self, data):
        for m in TOKEN.finditer(data):
            params, kind, text = m.groups()
            if text:
                for ch in text: self.put(ch)
            elif kind == "H":                              # ESC[row;colH
                r, c = (params.split(";") + ["1"])[:2]
                self.row, self.col = int(r or 1) - 1, int(c or 1) - 1
            elif kind == "J" and params == "2":            # ESC[2J
                self.cells = [[" "] * self.w for _ in range(self.h)]
            elif kind in ("h", "l") and params == "?25":   # show / hide cursor
                self.cursor_visible = kind == "h"
            # colours (m), synchronized updates (?2026) and OSC 8 links are ignored here

    def render(self):
        lines = ["".join(row).rstrip() for row in self.cells]
        return "\n".join(lines) + f"\ncursor: row {self.row + 1}, col {self.col + 1}"

cmd = ["herdr", "--session", sys.argv[1], "terminal", "session", "observe", sys.argv[2],
       "--cols", "10", "--rows", "4"]
screen = None
for line in subprocess.Popen(cmd, stdout=subprocess.PIPE, text=True).stdout:
    frame = json.loads(line)
    if frame["type"] != "terminal.frame":
        break                                              # terminal.closed
    if screen is None:
        screen = Screen(frame["width"], frame["height"])
    screen.apply(base64.b64decode(frame["bytes"]).decode())
    print(f"--- seq {frame['seq']} ({'full' if frame['full'] else 'patch'})")
    print(screen.render())
```

別のシェルから `hi`、Enter、`ok`、`日` をペインに打ちながら、`python3 -u mirror.py blog-herdr-demo w1:p1` を実行しました。レコードごとの出力です。

測りました。オブザーバーを動かしたまま 1 文字の `pane send-text` を 5 回実行し、コマンド開始の直前から、結果のフレームが届くまでを計りました。届くまでの時間は 5.9、12.2、12.7、12.8、15.4 ミリ秒で、コマンドが終わるより一瞬前に届いています（CLI の呼び出し自体は 6.2〜15.9 ミリ秒）。打った文字がどこかで待たされることはなく、コマンドが終了を終える前にエコーは返ってきています。

```bash
herdr --session blog-herdr-demo pane send-text w1:p1 "hi"
herdr --session blog-herdr-demo pane send-keys w1:p1 enter
```

覚えておきたいことが二つあります。テキストとキーは意図的に別物です。`send-text "hi"` は二文字を打ち、`enter` や `ctrl+c` のようなキーには文字の形がないので、名前で指定します。また、ドキュメントによればペインへの入力は、中で何が動いていても、そのターミナルに届きます。私のセッションでも、`cat` のペインに送った `ctrl+c` は `cat` を止め、ペインをシェルへ戻しました。それがこのコマンドの役目であり、危うさでもあります。

コマンドが終わったことを知るには、`pane wait-output` が画面の中の文字列を待ちます。ただし罠があり、私も踏みました。すでに画面にある文字、入力したコマンド行も対象にしてしまいます。

```bash
herdr --session blog-herdr-demo pane send-text w2:p1 'sleep 1; echo ready-$((6*7))'
herdr --session blog-herdr-demo pane send-keys w2:p1 enter
herdr --session blog-herdr-demo pane wait-output w2:p1 --match ready-42 --timeout 5000
```

最初は `echo ready-42` と書いてしまい、待ちは即座に返って、`"matched_line":"$ sleep 1; echo ready-42"`、つまり自分のコマンド行を返しました。`$((6*7))` を使うとコマンド行は `ready-$((6*7))` で、`ready-42` を含むのは出力だけです。出力が現れるまで待ち、`"matched_line":"ready-42"` で返ります。出力にしか現れない文字列で待ってください。

コーディングエージェントには `agent prompt` もあります。ドキュメントによれば、テキストと Enter を一つの順序づけられた送信として送り、ペインのブラケットペーストモードを守り、必要ならエージェントが落ち着くまで待ちます。テスト用セッションにエージェントがいなかったので、これは試していません。

## コントローラー：ブリッジが打てるのはいつか、ほかの人はどうなるか

`send-text` は一回きりのコマンドです。つなぎっぱなしの双方向接続（リモコンのようなもの）が欲しいなら、`terminal session control` を使います。`observe` と同じフレームのレコードを出力し、さらに標準入力から JSON のコマンドを読みます。同時に入力権を持てるコントローラーは一つだけで、このルールが見どころです。

図の三行は言い換えではありません。A が標準入力に送るのは `{"type":"terminal.input","text":"abc"}`。B が断られたときの記録は `{"reason":"terminal attach failed: terminal term_… already has an attached client; retry with --takeover","type":"terminal.closed"}`（ターミナル ID は短くしました）。A への別れの記録は `{"reason":"terminal attach taken over","type":"terminal.closed"}` です。コントローラーが `{"type":"terminal.release"}` を送ると、ストリームは `{"reason":"detached","type":"terminal.closed"}` で終わります。

実行で気づいた点が二つあります。

- `control` の `--cols` と `--rows` は表示領域の大きさを決め、その大きさが残ります。20×6 のコントローラーが去ったあとも、`herdr pane get` はそのペインを `viewport_rows: 6` と報告しました。ペインを自分だけが使っているのでなければ、残ってほしくない大きさは渡さないでください。
- ドキュメントによれば、リサイズもコントローラーが持ちます。コントローラーが送れるコマンドとして、ほかに `terminal.resize`、`terminal.scroll`、`terminal.mouse`（0 始まりのセルへのクリック。アプリがマウス報告を求めていなければ捨てられます）、`terminal.release` が挙げられています。私が試したのは入力と release だけです。

## まとめ：三つの小さなブリッジ

冒頭で挙げた三つのブリッジは、いずれもここまでの内容に数行足せば作れます。

**ミラー。** 上のスクリプトです。ペインに向ければ、格子とカーソルが自分のプログラムの中に保たれます。その格子を浮かぶウィンドウやウェブページ、スマートフォンに描けば、ミラーになります。

**リモコン。** 打つには `pane send-text` と `pane send-keys`、現れたかどうかは `pane wait-output --match`、結果を見るには `pane read`。コーディングエージェントには、ドキュメントにある経路として `agent prompt` があります。

**レコーダー。** 観察したレコードは一行ごとに JSON なので、記録は時刻を付けて行を保存するだけです。次のスクリプトは、あとで `Screen` クラスに流し込んで再生できるログを書きます。

```python
import json, subprocess, sys, time

t0 = time.monotonic()
cmd = ["herdr", "--session", sys.argv[1], "terminal", "session", "observe", sys.argv[2]]
for line in subprocess.Popen(cmd, stdout=subprocess.PIPE, text=True).stdout:
    print(json.dumps({"at": round(time.monotonic() - t0, 3), **json.loads(line)}), flush=True)
```

## 試していないこと

ここまでは、すべて自分のテスト用セッションで動かしました。次のものは herdr のドキュメントで読んだだけなので、プログラムについてではなく、ドキュメントの記述として受け取ってください。

- `agent prompt` と、エージェントの状態 `idle`、`working`、`blocked`、`done`。
- `terminal session control` の、入力と release 以外のコマンド（リサイズ、スクロール、マウス）。
- 直接アタッチ（`agent attach`、`terminal attach`）とリモートマシン。
- `recent` による、全画面エージェントの古いトランスクリプトの読み取り。ドキュメントによれば、エージェントがアイドルのとき herdr がエージェントのマウススクロール機能を使ってページ送りします。
- `events.subscribe` メソッド。スキーマには、この名前と `pane_output_changed` イベントがありますが、私は `observe` を使いました。

エージェント向けのドキュメント索引は [herdr.dev/llms.txt](https://herdr.dev/llms.txt)、CLI 自身のガイドは `herdr --skill` で表示できます。
